## Gotchas

- **WSL auto-upgrade kills everything, silently.** It ate the flagship this
  session. Launch long runs *detached from a real terminal* (`nohup … & disown`),
  not as a harness-session background task, and disable WSL auto-updates.
- **Don't run screens during the flagship's post-resume recompile** — CPU
  contention roughly doubled it (~30–45 min → ~90).
- **90M at batch-24 WDDM-thrashes the 16 GB 5080 when the flagship is running**
  (~15 GB reserved → spill, util 26%, ~0 progress). 30M screens are fine
  (~8 GB, ~20k tok/s). The Aug-2 90M control ran clean only because no flagship
  was competing.
- **`dstd>3.0` watchdog false-trips 2-layer 30M screens** at ~step 3000 (3
  occurrences). Set `watchdog_enabled: false` on short screens or they die
  half-trained. Threshold is hardcoded (`train_gpu.py:910`); the gate is not.
- **`recall_eval` OOMs loading two 363M models at B=128 on the 5080** — one
  model per process at B=64. (The "B=128 OK" note was the 32 GB 5090.)
- Windows-side edits to `\\wsl.localhost\...` strip +x and can add CRLF; run
  `sed -i 's/\r$//'` after, and invoke scripts as `bash /path/script.sh`.
- Passing a bare `/home/...` script path as a Bash-tool arg gets mangled by Git
  Bash (→ `D:/Program Files/Git/home/...`); keep it inside a quoted `bash -c`.
