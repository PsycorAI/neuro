## Gotchas

- WSL shell paths from Git-Bash need `MSYS2_ARG_CONV_EXCL="*"` prefix or leading `/` args get mangled to Windows paths.
- 5080 (16GB) OOMs at batch=32 on these configs; use batch=16/grad_accum=2 (eff batch held at 32).
- `data/vocab_map_32768.npy` = the Llama-3 subset (identity-LUT for train.bin's raw IDs); the from-scratch BPE variant was moved to `_freshbpe.npy`.
- Brain-corpus `.bin` files are uint32 raw Llama-3 IDs, not uint16 (bit `bake_brain.py`).
- **Launching background training via the harness's Bash tool: do NOT put `&`/nohup INSIDE the `wsl.exe -d ... -- bash -lc "cmd &"` string** — confirmed dead again tonight (empty log, no process survives) despite matching the exact anti-pattern already documented in `neuro_500m_v3_launched.md`. Fix (works): call the Bash tool with `run_in_background: true` wrapping `wsl.exe -d Ubuntu-G -- bash -lc "cmd"` with NO internal `&` — let the harness's own backgrounding keep the foreground `wsl.exe`/python process alive. Also: `$!`/`$VAR` diagnostics (e.g. `echo PID=$!`) silently print empty through this tool even when the command genuinely works — don't trust that output as a smoke test; verify via `nvidia-smi`/`ps aux`/log content instead.
